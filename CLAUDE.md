# CLAUDE.md — правила проекта «Сага Севера»

Ты главный разработчик прототипа мобильной idle RPG «Сага Севера» (Godot 4.7.2, только GDScript).
Заказчик — Дмитрий, не программист: ставит задачи, играет в сборки на iPhone, принимает этапы.

## С чего начать сессию

1. `docs/PROTOTYPE_SPEC.md` — исходное ТЗ.
2. `docs/SPEC_CHANGES.md` — утверждённые изменения ТЗ. **Важнее исходного ТЗ**; более поздний пункт важнее раннего.
   `docs/BACKLOG.md` — идеи Дмитрия на потом: не делать, пока он не возьмёт идею в работу.
3. Отчёт по последнему этапу в `../docs/MN.md` (старые отчёты — только если нужны).
4. `AGENTS.md` (правила ревью для Codex) и `README.md`.

## Где что лежит

- Папка заказчика: `~/Library/Mobile Documents/com~apple~CloudDocs/02 AI/Saga Severa/` (в пути пробелы — всегда в кавычках).
- `code.nosync/` — git-репозиторий с кодом (iCloud его не синхронизирует). Репозиторий: https://github.com/kozyrevdmit-create/saga-severa
- `../docs/` — отчёты для Дмитрия по этапам: `M1.md`, `M2.md`, … (синхронизируются через iCloud, в git не входят).
- Игра на сайте: https://kozyrevdmit-create.github.io/saga-severa/ (выкладывается GitHub Actions при каждом push в `main`).

## Процесс каждого этапа

1. Ветка от `main` → работа → тесты локально.
2. Pull request (описание по-русски) → отдельный комментарий `@codex review`.
3. **Убедиться, что Codex поставил 👀** на этот комментарий (обычно за 1–2 мин). Молчание не значит «проверяет»:
   нет 👀 за 3–5 мин — повторить `@codex review` отдельным комментарием и сказать Дмитрию.
4. Правки по замечаниям Codex → снова `@codex review` → сливать только после чистого ревью последнего коммита.
5. Слияние в `main` → дождаться выкладки → проверить на сайте самому (браузер с экраном размером с телефон).
6. Отчёт в `../docs/MN.md`.

Срочные мелочи (например, нужная заказчику кнопка) можно выкладывать отдельным маленьким PR раньше всего этапа — по тому же процессу.

## Правила кода

- **Цифры баланса — только в `data/*.json`** (HP, атака, награды, цены, рост, оффлайн-доход, суммы отладочной панели…). В `.gd` — ни констант, ни значений по умолчанию. Codex считает нарушение замечанием P1.
- **Логика боя отделена от экрана**: `scripts/battle/` без узлов сцены, ввода, реального времени и глобального `randi()/randf()`; вся случайность — через свой RNG с seed.
- Правила прогресса — в `scripts/save/progress.gd` (без экрана), экраны — в `scripts/ui/` и `scenes/`.
- Новое правило или формула — с тестом в `tests/`.
- **Решения фиксировать в `docs/SPEC_CHANGES.md`**: утверждённые заказчиком — в таблицу, свои трактовки неясных мест — в раздел «Трактовки».
- Ничего сверх ТЗ без вопроса Дмитрию. README держать актуальным.

## Команды (из `code.nosync/`)

```bash
godot --headless --path . --script res://tests/run_tests.gd        # тесты
godot --headless --path . --script res://tools/balance_sim.gd      # симуляция баланса (~1 мин)
godot --headless --path . --script res://tools/balance_sim.gd -- --until=6   # быстро: только этапы 1–6
```

Шаблонов веб-экспорта локально нет (интернет медленный): веб-сборку собирает GitHub Actions.
Экран можно проверить локально: `godot --path . --script <скрипт>` с сохранением `root.get_texture().get_image()` в PNG.

## Отчёты для Дмитрия

- На русском, простыми словами, без жаргона. Формат — как в `../docs/M4.md`:
  ссылка на игру и PR → что сделано (3–5 пунктов) → таблицы симуляции с пояснением → проверка на сайте (что сделал сам) →
  «Что проверить руками» (конкретно: открой, нажми, должно быть…) → «Что не получилось или под вопросом».
- Ручные действия для Дмитрия — пошагово, что именно нажать.

## Ограничения

- Во встроенном браузере сворачивание вкладки не срабатывает (фоновая вкладка не становится скрытой), а при закрытии панели браузера его хранилище стирается.
  **Оффлайн-сценарии (окно «Пока тебя не было») проверяет Дмитрий на iPhone** — в отчёте давать ему точные шаги.
