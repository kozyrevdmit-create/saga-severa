# Сага Севера

Прототип мобильной idle RPG (автобой отряда викингов с прокачкой). Движок Godot 4, язык GDScript. Графики нет: цветные прямоугольники с подписями.

**Играть в браузере:** https://kozyrevdmit-create.github.io/saga-severa/

Полное техническое задание: [docs/PROTOTYPE_SPEC.md](docs/PROTOTYPE_SPEC.md).

## Этапы

- [x] M1 — проект Godot, автовыкладка веб-версии, главный экран
- [x] M2 — бой фиксированного отряда против одной волны, ульты по нажатию
- [x] M3 — 10 этапов, прокачка, сохранение
- [x] M4 — расстановка отряда, роды, открытие героев, оффлайн-доход (+ карта главы, перепрохождение, уровень ярла)
- [ ] M5 — симуляция баланса, подбор цифр, отладочная панель

## Как запустить у себя

1. Скачать Godot **4.7.2** (обычную версию, не .NET): https://godotengine.org/download/archive/4.7.2-stable/
2. Запустить Godot → «Импорт» → выбрать файл `project.godot` из этой папки.
3. Нажать F5 (или кнопку ▶ вверху справа).

## Как обновляется веб-версия

Каждый push в ветку `main` запускает GitHub Actions ([.github/workflows/deploy-web.yml](.github/workflows/deploy-web.yml)):
тесты → сборка веб-версии (однопоточная, без особых заголовков сервера) → выкладка на GitHub Pages.
Если хоть один тест упал, сборка останавливается и на сайт ничего не выкладывается.
Для pull request прогоняются тесты и собирается веб-версия, без выкладки.
Статус сборок — вкладка **Actions** репозитория.

Собрать веб-версию локально (нужны шаблоны экспорта Godot 4.7.2: в Godot — «Редактор» → «Управление шаблонами экспорта» → «Загрузить»):

```bash
godot --headless --path . --export-release "Web" build/web/index.html
```

## Где что лежит

- `data/` — все цифры игры: герои, классы, роды (`heroes.json`), враги (`enemies.json`), этапы и волны (`stages.json`), общий баланс (`balance.json`). Менять баланс — только здесь, код трогать не нужно.
- `scripts/battle/` — правила боя без экрана (детерминированы: одинаковый seed — одинаковый бой).
- `scripts/save/` — прогресс игрока (серебро, опыт и уровень ярла, уровни и расстановка героев, пройденные этапы,
  время последнего визита для оффлайн-дохода) и сохранение в `user://save.json` (в браузере — в IndexedDB этого сайта).
  Сохраняется после каждого боя, прокачки и смены отряда, раз в минуту и при сворачивании.
- `tools/balance_sim.gd` — симуляция баланса.
- `scripts/ui/`, `scenes/` — экраны.
- `tests/` — тесты, запускаются без экрана.
- `AGENTS.md` — правила для ИИ-агентов, в том числе для ревью Codex.
- `docs/SPEC_CHANGES.md` — изменения ТЗ, утверждённые заказчиком после приёмки этапов.

## Тесты

Одна команда из папки проекта (на Mac `godot` ставится через `brew install --cask godot`):

```bash
godot --headless --path . --script res://tests/run_tests.gd
```

В конце печатается `N passed, 0 failed`. Код выхода 0 — всё хорошо, 1 — что-то упало (строки `FAIL` покажут что).
Те же тесты автоматически запускаются в GitHub Actions на каждый pull request и push в `main`.

## Симуляция баланса

Одна команда из папки проекта:

```bash
godot --headless --path . --script res://tools/balance_sim.gd
```

Печатает три таблицы:
1. Прохождение главы с нуля двумя игроками — «разумным» (серебро туда, где больше прирост силы отряда на монету)
   и «неидеальным» (серебро поровну между всеми героями): сколько раз каждый перепроходит предыдущий этап,
   где застревает, сколько улучшений покупает первая победа, сколько всего боёв и минут.
2. Процент побед по этапам на 1-м уровне и на уровнях разумного игрока (с ультами и без).
3. Среднее время зарядки ульты каждого героя.

Параметры: `-- --campaigns=40` (прохождений на игрока, по умолчанию 20), `-- --runs=200` (боёв на ячейку таблицы 2,
по умолчанию 100), `-- --level=12` (в таблице 2 все герои на заданном уровне). Около минуты.
